# requirements.md - 株価・財務データ取得方式の変更

対象: `.steering/20260905-market-data-source/`

## 背景

`docs/architecture.md` / `docs/functional-design.md` は当初「証券会社APIから取得済みの株価・財務データを読み込む」前提で設計していたが、ユーザーは証券会社の取引口座・APIを保有していないことが判明した。そのため、株価・財務データの取得方式を、口座を前提としない公的・無料のデータソースに変更する。

## 変更・追加する機能の説明

- 株価データ: **J-Quants API**(JPX(日本取引所グループ)提供、無料登録(メールアドレス+パスワード)で利用可能)から取得する
- 財務・開示情報: **EDINET API**(金融庁の開示書類閲覧システム、無料のSubscription-Key登録で利用可能)から、銘柄に関連する開示書類(有価証券報告書・決算短信等)の一覧を取得する
  - EDINETには「企業名や証券コードで検索するAPI」が存在しない。書類一覧は日付単位でしか取得できないため、直近N日分を日付ごとに取得し、証券コード(`secCode`)で絞り込む方式とする
  - 同じ日の書類一覧は全銘柄で共通のため、取得結果を日付単位でキャッシュし、無駄なAPI呼び出しを避ける
- 上記いずれのAPIキー(J-Quantsの認証情報、EDINETのSubscription-Key)も未設定の場合は、「未取得」であることを画面上に明示し、アプリ自体は動作を継続する(既存の検索シグナル調査機能はモックで動作継続するのと同じ考え方)

## ユーザーストーリー

- 個人投資家として、証券会社の口座を持っていなくても、監視銘柄の株価をアプリで確認したい。
- 個人投資家として、監視銘柄に関する直近の開示書類(決算短信・有価証券報告書等)への入り口をアプリから確認したい。
- 個人投資家として、APIキーを設定していない状態でもアプリ自体は壊れず、「未設定・未取得」であることが分かるようにしたい。

## 受け入れ条件

- `.env.example` にJ-Quants・EDINETの認証情報キーが追加されている
- J-Quantsの認証情報が設定されている場合、銘柄詳細画面の「データを更新」操作で当該銘柄の直近株価(終値等)を取得し表示できる
- EDINETのSubscription-Keyが設定されている場合、同操作で直近の開示書類一覧(書類名・提出日時・書類種別・EDINETへのリンク)を取得し表示できる
- 認証情報が未設定の場合はエラーで落ちず、「未設定」であることが画面に表示される
- EDINETの日次書類一覧はDBにキャッシュされ、同じ日付を複数銘柄・複数回の更新で重複取得しない
- `npm run lint` / `npm run typecheck` / `npm run test` / `npm run build` が成功する

## 制約事項

- EDINET APIには企業名・証券コードによる横断検索が存在しないため、直近の一定日数(既定30日、環境変数で調整可能)を日付ごとに走査する方式とする。これにより「直近の開示」は概ね捕捉できるが、決算発表サイクル次第では取りこぼす可能性がある(既知の制約として `docs/architecture.md` に明記する)
- J-Quantsの無料プランは株価データの提供に数週間程度のタイムラグがある場合がある(既知の制約として明記する)
- 本変更は`docs/architecture.md`・`docs/functional-design.md`・`docs/glossary.md`の該当箇所を更新した上で実装する
